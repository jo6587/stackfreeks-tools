Nextcloud 서버 요구사항 계산기 소개

Nextcloud 성능은 등록된 사용자 계정 수가 아니라 서버가 동시에 처리하는 PHP 요청 수에 좌우됩니다. 사용자 500명 중 피크에 20명만 동기화하는 서버는, 사용자 100명이 모두 웹 UI에서 활동하는 서버와 완전히 다르게 동작합니다. 이 계산기는 사용자 수, 예상 동시 접속자, 평균 스토리지 할당량, 워크로드 프로필을 입력받아 하드웨어 요구사항 — vCPU, RAM(GB), 오버헤드 포함 총 스토리지(GB), PHP-FPM 워커 수, Redis 및 전용 데이터베이스 추가 여부 — 를 추정합니다.

이 휴리스틱은 공개된 Nextcloud 사이징 가이드를 기준으로 합니다: PHP 프로세스당 최소 약 128MB, 권장 512MB RAM, 사용자 10명 미만은 총 2-4GB RAM, 10-100명은 8-16GB, 100명 초과 또는 미디어 중심 배포는 32GB 이상. VPS에 Nextcloud를 셀프호스팅하려는 사람, 가정·소기업 파일 서버를 산정하는 사람, Dropbox나 Google Drive에서 이전하기 전에 Vultr 인스턴스를 적정 사이즈로 맞추려는 사람에게 유용합니다. 모든 상수는 페이지 소스의 주석 처리된 객체 하나에서 조정할 수 있습니다.

계산기 사용 방법

1. 사용자 수 입력

호스팅할 Nextcloud 계정의 총 개수를 입력하세요.

2. 동시 접속 설정

"자동"을 켜두면 피크에 사용자의 약 10%가 활동한다고 가정하고, 끄면 직접 동시 접속자 수를 입력합니다.

3. 워크로드 & 스토리지 선택

가벼운 동기화, 오피스+그룹웨어, 미디어+무거운 앱 중 선택하고, 사용자당 평균 GB를 설정한 뒤 미리보기 생성이나 전문 검색을 켜세요.

4. 추천 결과 확인

vCPU, RAM, 오버헤드 포함 스토리지, PHP-FPM 워커 수, Redis·전용 DB 권장 여부와 여유분을 반영한 Vultr 플랜을 확인하세요.

자주 묻는 질문

최소 단일 사용자 설치의 경우 Nextcloud는 약 512MB RAM, CPU 1코어, 지원되는 PHP 버전(현재 릴리스는 8.1 이상), 웹 서버(Apache 또는 Nginx), 데이터베이스(MariaDB, MySQL 또는 PostgreSQL, SQLite는 테스트용만)가 필요합니다. 실제 배포에는 훨씬 더 많은 자원이 필요합니다. 공식 가이드는 사용자 10명 미만은 약 2-4GB RAM, 10-100명은 8-16GB, 그 이상은 32GB 이상을 권장하며, APCu 같은 메모리 캐시와 파일 잠금용 Redis도 필요합니다. 이 계산기는 원시 사용자 수가 아니라 실제 부하를 유발하는 동시 PHP 요청 수를 기준으로 CPU와 RAM을 산정합니다.
Nextcloud 자체는 약 512MB로 시작할 수 있지만, 요청을 처리하는 각 PHP-FPM 워커는 보통 최소 128MB를 사용하고 512MB가 안전한 권장 상한이므로, RAM은 동시에 처리하는 요청 수에 따라 증가합니다. 대략적인 기준: 사용자 10명 미만의 가정·소규모 팀 서버는 2-4GB, 10-100명은 8-16GB, 100명 이상이거나 미리보기 생성·전문 검색이 있는 미디어 중심 워크로드는 32GB 이상. Redis와, 같은 호스트에 있다면 데이터베이스용 메모리도 추가하세요. 이 도구는 OS 기본값, PHP 워커, 캐시, 선택적 서비스를 합산한 뒤 여유분을 위해 다음 Vultr 플랜으로 올림합니다.
오피스·그룹웨어 워크로드의 사용자 50명은 10-100명 구간의 중간에 해당하며, 공식 가이드는 이를 약 8-16GB RAM과 4개 이상의 vCPU로 봅니다. 피크 동시 접속률 약 10%면 동시 사용자 약 5명이므로, PHP-FPM 워커 약 8-16개를 실행하고 트랜잭션 파일 잠금을 위해 APCu와 Redis를 활성화하며, 워크로드가 무겁지 않은 한 데이터베이스는 같은 호스트에 두면 됩니다. 스토리지는 사용자당 할당량에 따라 다릅니다: 사용자 50명 × 20GB는 원시 데이터 1TB이며, 파일 버전·휴지통·썸네일을 위해 약 30%를 추가로 확보해야 합니다.
단일 사용자 설치에는 Redis가 반드시 필요하지는 않지만, 동시 사용자가 있는 경우에는 강력히 권장됩니다. Nextcloud는 여러 클라이언트가 같은 파일을 동기화할 때 파일 손상을 방지하는 트랜잭션 파일 잠금에 Redis를 사용하고, APCu와 함께 빠른 로컬 메모리 캐시로도 사용합니다. 동시 사용자가 몇 명을 넘거나 데스크톱·모바일 동기화 클라이언트를 대규모로 운영하면, Redis 없이는 잠금 오류와 느린 대시보드가 발생합니다. 이 계산기는 예상 동시 PHP 요청이 낮은 임계값을 넘거나 사용자 수가 약 20명을 넘으면 Redis 추가를 권장합니다.
네. VPS는 Nextcloud를 셀프호스팅하는 가장 일반적인 방법 중 하나입니다. RAM 2GB, vCPU 1-2개의 작은 인스턴스는 개인·소규모 팀 서버를 무리 없이 실행하고, RAM 8GB 이상의 큰 플랜은 수십 명의 사용자를 처리합니다. 주요 제약은 PHP 워커용 RAM, 사용자 파일과 약 30% 오버헤드를 위한 디스크 공간, 동기화 트래픽을 위한 충분한 대역폭입니다. Vultr 같은 제공업체는 사용자가 늘면 플랜을 리사이즈할 수 있고, 블록 스토리지를 별도로 연결해 데이터를 부팅 디스크에 두지 않을 수 있습니다.
