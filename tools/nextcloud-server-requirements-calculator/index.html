About this Nextcloud server requirements calculator

Nextcloud performance is driven by how many PHP requests the server handles at the same time, not by how many user accounts exist. A server with 500 users where only 20 sync at peak behaves very differently from one with 100 users who are all active in the web UI at once. This calculator estimates hardware requirements — vCPU, RAM in GB, total storage in GB including overhead, PHP-FPM worker count, and whether you should add Redis and a dedicated database — from your user count, expected concurrency, average storage quota, and workload profile.

The heuristic anchors to published Nextcloud sizing guidance: roughly 128 MB minimum and 512 MB recommended RAM per PHP process, about 2-4 GB total RAM for fewer than 10 users, 8-16 GB for 10-100 users, and 32 GB or more beyond 100 users or for media-heavy deployments. It is useful for anyone planning to self-host Nextcloud on a VPS, sizing a family or small-business file server, or right-sizing a Vultr instance before migrating off Dropbox or Google Drive. All constants are tunable in one clearly commented object in the page source.

Frequently asked questions

For a minimal single-user install Nextcloud needs about 512 MB of RAM, one CPU core, a supported PHP version (8.1 or newer for current releases), a web server (Apache or Nginx), and a database (MariaDB, MySQL, or PostgreSQL; SQLite only for testing). Real deployments need much more: the project's own guidance suggests roughly 2-4 GB RAM for fewer than 10 users, 8-16 GB for 10-100 users, and 32 GB or more beyond that, plus a memory cache such as APCu and Redis for file locking. This calculator sizes CPU and RAM from concurrent PHP requests rather than raw user count, which is the metric that actually drives load.
Nextcloud itself can start in around 512 MB, but each PHP-FPM worker handling a request typically uses 128 MB at minimum and 512 MB is a safe recommended ceiling, so RAM scales with how many requests you serve at once. A rough guide: 2-4 GB for a home or small-team server under 10 users, 8-16 GB for 10-100 users, and 32 GB or more for 100+ users or media-heavy workloads with preview generation and full-text search. Add memory for Redis and, if co-located, the database. This tool adds up the OS baseline, PHP workers, cache, and optional services, then rounds up to the next Vultr plan for headroom.
Fifty users on an office and groupware workload land in the middle of the 10-100 user band, which published guidance puts at roughly 8-16 GB RAM and 4 or more vCPUs. With around 10% peak concurrency that is about 5 concurrent users, so you would run roughly 8-16 PHP-FPM workers, enable APCu plus Redis for transactional file locking, and keep the database on the same host unless the workload is heavy. Storage depends on your quota per user: 50 users at 20 GB each is 1 TB of raw data, and you should budget about 30% on top for file versions, trash, and thumbnails.
Redis is not strictly required for a single-user install, but it is strongly recommended for anything with concurrent users. Nextcloud uses Redis for transactional file locking, which prevents file corruption when multiple clients sync the same file, and as a fast local memory cache alongside APCu. Once you have more than a handful of simultaneous users or run the desktop and mobile sync clients at scale, running without Redis leads to locking errors and slow dashboards. This calculator recommends adding Redis once estimated concurrent PHP requests exceed a low threshold or the user count passes about 20.
Yes. A VPS is one of the most common ways to self-host Nextcloud. A small instance with 2 GB RAM and 1-2 vCPUs comfortably runs a personal or small-team server, while larger plans with 8 GB or more handle dozens of users. The main constraints are RAM for PHP workers, disk space for user files plus roughly 30% overhead, and enough bandwidth for sync traffic. Providers like Vultr let you resize the plan as your user base grows, and block storage can be attached separately so data does not have to live on the boot disk.

자주 묻는 질문

최소 단일 사용자 설치의 경우 Nextcloud는 약 512MB RAM, CPU 1코어, 지원되는 PHP 버전(현재 릴리스는 8.1 이상), 웹 서버(Apache 또는 Nginx), 데이터베이스(MariaDB, MySQL 또는 PostgreSQL, SQLite는 테스트용만)가 필요합니다. 실제 배포에는 훨씬 더 많은 자원이 필요합니다. 공식 가이드는 사용자 10명 미만은 약 2-4GB RAM, 10-100명은 8-16GB, 그 이상은 32GB 이상을 권장하며, APCu 같은 메모리 캐시와 파일 잠금용 Redis도 필요합니다. 이 계산기는 원시 사용자 수가 아니라 실제 부하를 유발하는 동시 PHP 요청 수를 기준으로 CPU와 RAM을 산정합니다.
Nextcloud 자체는 약 512MB로 시작할 수 있지만, 요청을 처리하는 각 PHP-FPM 워커는 보통 최소 128MB를 사용하고 512MB가 안전한 권장 상한이므로, RAM은 동시에 처리하는 요청 수에 따라 증가합니다. 대략적인 기준: 사용자 10명 미만의 가정·소규모 팀 서버는 2-4GB, 10-100명은 8-16GB, 100명 이상이거나 미리보기 생성·전문 검색이 있는 미디어 중심 워크로드는 32GB 이상. Redis와, 같은 호스트에 있다면 데이터베이스용 메모리도 추가하세요. 이 도구는 OS 기본값, PHP 워커, 캐시, 선택적 서비스를 합산한 뒤 여유분을 위해 다음 Vultr 플랜으로 올림합니다.
오피스·그룹웨어 워크로드의 사용자 50명은 10-100명 구간의 중간에 해당하며, 공식 가이드는 이를 약 8-16GB RAM과 4개 이상의 vCPU로 봅니다. 피크 동시 접속률 약 10%면 동시 사용자 약 5명이므로, PHP-FPM 워커 약 8-16개를 실행하고 트랜잭션 파일 잠금을 위해 APCu와 Redis를 활성화하며, 워크로드가 무겁지 않은 한 데이터베이스는 같은 호스트에 두면 됩니다. 스토리지는 사용자당 할당량에 따라 다릅니다: 사용자 50명 × 20GB는 원시 데이터 1TB이며, 파일 버전·휴지통·썸네일을 위해 약 30%를 추가로 확보해야 합니다.
단일 사용자 설치에는 Redis가 반드시 필요하지는 않지만, 동시 사용자가 있는 경우에는 강력히 권장됩니다. Nextcloud는 여러 클라이언트가 같은 파일을 동기화할 때 파일 손상을 방지하는 트랜잭션 파일 잠금에 Redis를 사용하고, APCu와 함께 빠른 로컬 메모리 캐시로도 사용합니다. 동시 사용자가 몇 명을 넘거나 데스크톱·모바일 동기화 클라이언트를 대규모로 운영하면, Redis 없이는 잠금 오류와 느린 대시보드가 발생합니다. 이 계산기는 예상 동시 PHP 요청이 낮은 임계값을 넘거나 사용자 수가 약 20명을 넘으면 Redis 추가를 권장합니다.
네. VPS는 Nextcloud를 셀프호스팅하는 가장 일반적인 방법 중 하나입니다. RAM 2GB, vCPU 1-2개의 작은 인스턴스는 개인·소규모 팀 서버를 무리 없이 실행하고, RAM 8GB 이상의 큰 플랜은 수십 명의 사용자를 처리합니다. 주요 제약은 PHP 워커용 RAM, 사용자 파일과 약 30% 오버헤드를 위한 디스크 공간, 동기화 트래픽을 위한 충분한 대역폭입니다. Vultr 같은 제공업체는 사용자가 늘면 플랜을 리사이즈할 수 있고, 블록 스토리지를 별도로 연결해 데이터를 부팅 디스크에 두지 않을 수 있습니다.
