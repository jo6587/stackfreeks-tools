How to Use

    

      

        
1. Pick the server role

        
A Proxmox or VM host needs RAM for guests, so the ARC follows the Proxmox wiki storage rule. A dedicated NAS can give most RAM to the ARC. Mixed sits in between.

      

      

        
2. Enter RAM, pool size and reserve

        
Use free -g for RAM and zpool list for pool size. The reserve is the RAM that must stay outside the ARC for VMs, containers and the OS; the ARC is never set above RAM minus that reserve.

      

      

        
3. Copy zfs.conf and apply

        
Put the options line in /etc/modprobe.d/zfs.conf. If root is on ZFS, run update-initramfs -u -k all and reboot. To try a value first, write it to /sys/module/zfs/parameters/zfs_arc_max.

      

      

        
4. Verify and watch

        
cat the parameter to confirm the byte value, then check arc_summary over a few busy days. If the hit rate is low and RAM is free, raise the limit; if the host swaps, lower it.

      

    

  

  

    
사용 방법

    

      

        
1. 서버 용도 고르기

        
Proxmox·VM 호스트는 게스트에 줄 RAM이 필요하므로 Proxmox 위키의 스토리지 기준을 따릅니다. 전용 NAS는 RAM 대부분을 ARC에 줄 수 있고, 혼합은 그 중간입니다.

      

      

        
2. RAM·풀 용량·예약 메모리 입력

        
RAM은 free -g, 풀 용량은 zpool list로 확인하세요. 예약 메모리는 VM·컨테이너·OS를 위해 ARC 밖에 남겨 둘 RAM이며, ARC는 RAM에서 이 값을 뺀 크기를 넘지 않게 잡힙니다.

      

      

        
3. zfs.conf 복사 후 적용

        
options 줄을 /etc/modprobe.d/zfs.conf에 넣으세요. 루트가 ZFS면 update-initramfs -u -k all 후 재부팅합니다. 먼저 시험해 보려면 /sys/module/zfs/parameters/zfs_arc_max에 값을 쓰면 됩니다.

      

      

        
4. 확인하고 지켜보기

        
파라미터를 cat으로 읽어 바이트 값을 확인하고, 바쁜 날 며칠 동안 arc_summary를 보세요. 적중률이 낮고 RAM이 남으면 올리고, 호스트가 스왑을 쓰면 내리세요.

      

    

  

  


  
  

  

    
Frequently Asked Questions

    

      
      
There is no single right number. The Proxmox VE wiki gives a rule of thumb of at least 2 GiB base plus 1 GiB per TiB of storage, which suits a VM host where guests need the rest of the RAM. A dedicated NAS can give the ARC much more, because nothing else needs the memory. Treat any value as a starting point, then watch the ARC hit rate and memory pressure and adjust.

    

    

      
      
The module parameter defaults to 0, which means ZFS picks the limit from installed memory. The OpenZFS 2.2 man page says Linux uses half of system memory. The OpenZFS 2.3 man page says the larger of system memory minus 1 GiB and 5/8 of system memory. Proxmox VE 8.1 and later installers write their own limit to /etc/modprobe.d/zfs.conf: 10% of RAM, clamped to 16 GiB. Run zfs version to see which OpenZFS you have.

    

    

      
      
The Proxmox wiki explains that zfs_arc_max is ignored when it is lower than or equal to zfs_arc_min, which defaults to the larger of 32 MiB and 1/32 of system memory. In that case also set zfs_arc_min to at most zfs_arc_max minus 1 byte. zfs_arc_max must also be at least 64 MiB. If your root file system is on ZFS, run update-initramfs -u -k all and reboot, or the old value is loaded at boot.

    

    

      
      
zfs_arc_max is written in bytes. Multiply the GiB value by 1073741824 (1024 × 1024 × 1024). For example 8 GiB is 8589934592 and 10 GiB is 10737418240. The converter on this page works both ways, so you can also paste the number from an existing zfs.conf to see it in GiB and as a share of your RAM.

The OpenZFS man page notes that lowering the limit below the current ARC size does not shrink the ARC until there is memory pressure, and the value cannot be set back to 0 while running.

모듈 파라미터 기본값은 0이며, 이때 ZFS가 설치된 메모리로 한도를 정합니다. OpenZFS 2.2 man 페이지는 리눅스에서 시스템 메모리의 절반을 쓴다고 하고, OpenZFS 2.3 man 페이지는 "시스템 메모리 − 1GiB"와 "시스템 메모리의 5/8" 중 큰 값이라고 합니다. Proxmox VE 8.1 이상 설치 프로그램은 RAM의 10%(최대 16GiB)를 /etc/modprobe.d/zfs.conf에 따로 적습니다. 쓰는 버전은 zfs version으로 확인하세요.

    

    

      
      
Proxmox 위키에 따르면 zfs_arc_max가 zfs_arc_min(기본값: 32MiB와 시스템 메모리의 1/32 중 큰 값) 이하이면 무시됩니다. 이때는 zfs_arc_min도 zfs_arc_max − 1바이트 이하로 함께 설정하세요. zfs_arc_max는 최소 64MiB여야 합니다. 루트 파일 시스템이 ZFS라면 update-initramfs -u -k all 후 재부팅해야 부팅 때 새 값이 적용됩니다.
