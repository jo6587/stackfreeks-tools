    사용 방법

    1. 프리픽스 입력

    주소와 프리픽스 길이를 함께 입력하세요. 예: 2001:db8:1234::/56. :: 축약형과 ::ffff:192.0.2.1 같은 IPv4 포함 표기도 됩니다. /프리픽스를 빼면 /64로 계산합니다.

    2. 분할할 프리픽스 선택

    나눌 서브넷의 프리픽스 길이를 정하세요. LAN은 /64(SLAAC 필수), 다른 지점이나 고객에게 블록을 나눠 줄 때는 /60이나 /56을 씁니다.

    3. 결과 확인

    서브넷 개수, 네트워크, 첫·마지막 주소, 정확한 전체 주소 수, 축약·확장 표기, ip6.arpa 역방향 존, 주소 유형을 보여줍니다. /64가 아닌 LAN이나 니블 경계가 아닌 프리픽스는 경고로 알려줍니다.

    4. 목록 탐색과 내보내기

    하위 서브넷을 페이지별로 넘겨 보거나 서브넷 #N으로 바로 이동하고, 현재 페이지를 복사하거나 CSV로 내려받아 IPAM·설정 파일에 쓰세요.

    자주 묻는 질문

    /48에는 216 = 65,536개, /56에는 28 = 256개의 /64 서브넷이 들어갑니다. 일반적으로 /p 프리픽스에는 2(64 - p)개의 /64가 있습니다. 프리픽스가 1비트 길어질 때마다 서브넷 수가 두 배가 되기 때문입니다. 위에 프리픽스를 입력하면 정확한 개수와 전체 주소 수를 정수 그대로 보여줍니다.
    SLAAC(RFC 4862)는 64비트 인터페이스 식별자로 호스트 주소를 만들기 때문에 자동 주소 설정은 /64에서만 동작합니다. /80, /112처럼 더 긴 프리픽스에서는 고정 주소나 DHCPv6가 필요합니다. 라우터 간 point-to-point 링크(/127, RFC 6164)나 루프백(/128)에는 긴 프리픽스를 써도 됩니다.
    RFC 5952는 표준 텍스트 표기를 하나로 정합니다: 16진수 소문자, 그룹 앞자리 0 생략, 0으로만 된 그룹이 2개 이상 이어지는 가장 긴 구간을 ::로 대체(길이가 같으면 왼쪽 구간). 0 그룹 하나는 ::로 줄이지 않습니다. 확장 표기는 8개 그룹을 모두 16진수 4자리로 쓰며, 역방향 DNS나 정렬에 필요합니다.
    역방향 존은 니블(4비트, 16진수 한 자리) 단위로 위임됩니다. 확장된 프리픽스의 16진수 자릿수를 거꾸로 뒤집어 점으로 구분하고 ip6.arpa를 붙입니다: 2001:db8:1234::/56은 0.0.4.3.2.1.8.b.d.0.1.0.0.2.ip6.arpa가 됩니다. /57처럼 4의 배수가 아닌 프리픽스는 존 하나로 만들 수 없어 /60 존 8개가 필요하며, 계산기는 첫 존과 개수를 보여줍니다.
    RFC 6177은 최종 사이트에 /64 하나보다 큰 블록, 보통 /48이나 /56을 주도록 권장합니다. 가정용 ISP는 DHCPv6 프리픽스 위임으로 /56이나 /60을 주는 경우가 많고, 많은 VPS 업체는 서버마다 /64를 라우팅합니다. 정확한 크기는 업체마다 다르니 관리 화면에서 확인한 뒤 여기에 입력해 서브넷을 계획하세요.
